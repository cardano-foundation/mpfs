# Patched HTTP client for MPFS

An MPFS client operator needs the ordinary token, fact and transaction HTTP calls to retain their request/response behavior while the installed Axios 1.x family no longer matches its captured high-severity advisories. A contributor needs the source-imported HTTP client declared as a direct runtime dependency, rather than supplied accidentally through Mesh.

Bind implementation to the accepted Node 24 prerequisite and the unchanged Aiken validator. Refresh the per-occurrence ledger at intake, choose a supported Axios 1.x patch outside all targeted vulnerable ranges and update every compatible 1.x occurrence. The approved planning candidate was 1.20.0. Preserve the older Axios 0.x family for the separate SDK migration, unless parent-aware resolution naturally removes it; do not force it across its declared caret range. Keep the change focused on this family and its necessary dependency edges.

Acceptance requires meaningful security regression evidence against the old HTTP dependency, real HTTP/client compatibility, frozen installation, the complete service and Aiken gates, exact-image execution, exact-head hosted CI and a confirmed preprod transaction journey. Twelve high-alert closures are a target, not a claim before GitHub rescans. Publish any remaining occurrences and new findings.
